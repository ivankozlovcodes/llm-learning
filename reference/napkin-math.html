The core formulas

bytes per token (GB) = active params (B) × bits per weight ÷ 8
memory footprint (GB) = total params (B) × bits per weight ÷ 8
tok/s ceiling = bandwidth (GB/s) ÷ bytes per token (GB)
tok/s realistic = ceiling × efficiency (0.6 – 0.85) decode only, single stream, weights only
The distinction that does the work

Capacity comes from total parameters. Speed comes from active parameters. For a dense model they are the same number, which is why the distinction only becomes visible — and decisive — with Mixture-of-Experts models.

The cost of a turn

turn time = prompt tokens ÷ prefill rate + output tokens ÷ decode rate
time to first token = prompt tokens ÷ prefill rate prefill is compute-bound · decode is bandwidth-bound

With prefix cache reuse, "prompt tokens" means only the newly appended tokens. Without it, it means the entire conversation, every turn — and session cost becomes quadratic.

PrefillComputeGPU cores / TFLOPSMatrix–matrix, high arithmetic intensity

Rules of thumb

1. A dense model at Q4_K_M occupies about 0.6 GB per billion parameters. 70B → ~42 GB. 32B → ~20 GB. 8B → ~5 GB.
2. Halving bits per weight doubles decode speed and halves memory. Quantization is a speed decision as much as a fit decision.
3. If measured speed is far below the predicted realistic figure, suspect a configuration fault, not weak hardware — usually the model has spilled out of fast memory.
4. Leave 15–25% headroom above the weights for the KV cache and the system. A model that exactly fits does not actually fit.
5. For MoE, divide by active parameters for speed and by total for whether it loads at all.
6. Bandwidth and capacity are independent axes. Decide which one your workload is actually short of before comparing prices.
7. Prefill is roughly 10× decode on a balanced machine and up to 300× on a compute-heavy one. Check the ratio before assuming a machine is "fast".
8. In an agent loop, cache reuse beats every hardware upgrade. It converts a quadratic session into a linear one.
9. Cache reuse dies the moment the prefix changes. Timestamps in system prompts, history trimming, and reordered tool definitions are all cache invalidations.
10. Budget the KV cache before the weights. At agent-scale context it is routinely 20–25% of the footprint, and it is the reason a model that "fits" stops fitting mid-session.
11. Prefer a small-active MoE with few KV heads for agent work. It wins decode speed and cache size simultaneously — the two things a long-context loop is short of.
12. Compaction is a priced trade: it buys memory with one uncached turn. Rare and deep beats frequent and shallow.
13. Ignore TOPS. It rates a resource decode never exhausts. Find bandwidth and capacity; if a vendor omits bandwidth, infer it from memory type and bus width.
14. 8 GB is a wall, not a tier. An 8B model plus an agent-scale cache does not fit, whatever the token rate says.
15. Audit any vendor tok/s claim: multiply it by the model's size in GB. If the result exceeds the part's bandwidth, the claim is wrong.
16. Stay at or above 4 bits, then take the largest model that fits there. Reasoning degrades ~2.3× faster than average scores show.
17. Never trust a quant label. File size × 8 ÷ params gives the real bits per weight; "1-bit" is routinely 1.8–2.0.
18. On a memory-starved machine, quantize the KV cache before the weights. Q8 cache is nearly free; low-bit weights are not.

Scope

This sheet covers decode (Lesson 1), prefill and turn cost (Lesson 2), and the KV cache budget (Lesson 3), all at batch 1. Together they are enough to price any model on any machine from published specs. Still missing: batching, which raises decode throughput sharply while leaving prefill flat, and everything about model capability — tool-calling reliability and structured output, which no amount of bandwidth fixes.
