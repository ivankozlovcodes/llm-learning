The Quantization Ladder

Five lessons have told you to quantize without once pricing what it costs. The bill comes due in a specific place — and it is exactly the place an agent harness depends on.

~20 minutes Prerequisite: Lesson 5 Mission · Glossary · Cheat sheet
The one idea

Quantization does not degrade a model evenly. Recall survives; reasoning breaks. Between 4-bit and 3-bit, an aggregate benchmark score falls about 4 points while multi-step reasoning falls 9.3 — and commonsense recall barely moves at all.

Averaged scores hide this. Tool calling and agent loops are multi-step reasoning, so you feel the damage precisely where you least want it.

Reading the names

Every GGUF filename encodes its scheme. Once you can parse it, the whole ladder is legible:

UD – IQ4_XS recipe · family · nominal bits · variant
PartMeans
Q4_0, Q4_1Legacy. Uniform block scaling, simple and superseded. Worse quality than a K-quant of the same nominal width.
Q4_K_MK-quant. Super-blocks of 256 weights with hierarchical scales. S/M/L = small/medium/large variant, which controls how many tensors get extra bits.
IQ4_XSI-quant. Codebook/lattice-based, built with an importance matrix. Better quality per bit than K-quants, especially below 4 bits — but more work to decode.
UD- prefixUnsloth Dynamic. Not a format — a recipe. Each layer gets whichever type minimises loss for that specific model.
_XL, _XXSHow far the recipe pushes: XL keeps more tensors high-precision, XXS strips harder.

Why the bits are never the number on the tin

Quantization is block-wise: weights are split into blocks, and each block stores its own scale (and often a minimum) alongside the quantized values. That metadata is real storage. A 256-weight super-block at 4 bits holds 128 bytes of weights plus scales and mins — so Q4_K_M lands near 4.9 effective bpw, not 4.0.

Which is why the only trustworthy way to size a model is the one you saw in Lesson 5: take the actual file size and divide by the parameter count.

effective bpw = file size (bytes) × 8 ÷ parameter count the label is marketing · this is the number

Read the last row carefully. HellaSwag is flat everywhere. If you evaluated quantization on recall-style benchmarks you would conclude 3-bit is nearly free. It is not — it just took its payment somewhere else, out of the chain-of-reasoning behaviour that a tool-calling agent runs on every single turn.

Why reasoning first? A recall answer needs one approximately-right activation. A multi-step chain needs every step right; small per-step errors compound. Quantization adds a little noise to every weight, and compounding is exactly what a long chain does to noise.

The speed dividend

The same study measured throughput, and it lands exactly where Lesson 1 said it would — fewer bytes per token, more tokens per second:

One wrinkle the bandwidth rule alone does not predict: i-quants decode more slowly per byte than k-quants. Their codebook lookups cost real compute, so an IQ3 file will not hit the ceiling that a Q3_K file of the same size does. On a bandwidth-starved machine that trade is usually still worth it; on a fast GPU it often is not.

Importance matrices, and how 1.81 bits is possible

Not all weights matter equally. An importance matrix (imatrix) is built by running calibration text through the model and recording which weights actually influence outputs. The quantizer then spends bits where they matter and starves the rest.

Unsloth Dynamic (UD-) takes this further: rather than one scheme for the whole model, it picks a per-layer type from an analysis of that specific model, calibrated on a mix aimed at agentic coding, chat and multilingual use. The layers protected in Gemma differ from those protected in Llama.

Which brings us back to your 27B:

6.19 GB × 8 ÷ 27.3B params = 1.81 bits per weight Qwen3.8-27B UD-IQ1_S — an 89% reduction from BF16

"1-bit" is the family name, not the measurement. Some tensors sit near 1 bit; attention and embedding layers are kept far higher; the average is 1.81. Unsloth report this build retaining roughly 72% top-1% accuracy against the unquantized model — a real achievement, and still a substantial capability loss.

When extreme quantization is legitimate

Good case: a very large model, especially a big MoE, where parameter redundancy absorbs the noise. A 235B at 2 bits often beats a 30B at 5 bits, because there is simply more model left after the damage.

Bad case: a small or mid-size dense model, where every weight is already doing work. A 27B dense at 1.81 bpw has no redundancy to spend — and on your 8 GB machine it does not fit anyway.

The question this all builds to

You have a fixed byte budget. Bigger model quantized harder, or smaller model treated gently?

Same ~2.5 GB budgetbpwExpected behaviour
Qwen3-4B at Q4_K_M4.98Above the bend. Reasoning intact.
Qwen3-8B at ~Q22.4Below the bend. More knowledge, degraded reasoning.

The working rule: stay at or above 4 bits, then take the largest model that fits. Cross below 4 only when the model is large enough to have redundancy to spare. For agent work the rule is stricter still, because tool calling lives on the reasoning curve, not the recall one — and a harness that emits one malformed call in ten is worse than a slower harness that emits none.

Check yourself

Question 1

Going from 4-bit to 3-bit, which capability degrades most?

Multi-step reasoning. GSM8K fell 9.32 points while HellaSwag stayed within ±1 and the five-benchmark aggregate fell under 4. Errors compound along a chain, and quantization noise is applied to every weight in it. Throughput moved the other way — 3-bit is 3.5× faster.
Question 2

Why is Q4_K_M about 4.9 bits per weight rather than 4.0?

Block scales cost storage. Weights are quantized in super-blocks, and each stores its own scale and minimum alongside the values. That metadata is real, so effective bpw always exceeds nominal. Some tensors are also kept at higher precision, which adds to it — but the block metadata is the structural reason.
Question 3

A file is 6.19 GB for a 27.3B-parameter model. What is its effective bits per weight?

~1.81 bits. 6.19 × 10⁹ × 8 ÷ 27.3 × 10⁹. This is the calculation that lets you ignore every quant label you are shown: file size and parameter count are both published, so the real number is always available to you.
Question 4

Fixed byte budget for an agent harness. Which choice is generally right?

Smaller model at 4 bits. Stay above the bend, then take the largest model that fits there. The exception is very large sparse models — a 235B MoE at 2 bits has redundancy a 27B dense model does not. For tool-calling work the rule tightens, since reliability lives on the reasoning curve that low-bit quantization damages first.
